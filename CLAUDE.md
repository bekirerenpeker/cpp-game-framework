# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A 2D Terraria-style game written in C++20, built on a custom engine. The repo is split into a reusable **engine** static library and a thin **game** executable that currently drives it through hand-written test scenes rather than a real gameplay loop.

## Build & Run

The project uses CMake. VS Code is configured to use the **Ninja** generator and copies `compile_commands.json` to the repo root for clangd.

```bash
# First-time setup: init the git submodules (glfw, miniaudio, nlohmann_json,
# freetype, msdf-atlas-gen — the last one pulls msdfgen recursively)
git submodule update --init --recursive
```

`freetype` + `msdf-atlas-gen` are only needed to **bake** a font atlas. They are
gated behind the `ENGINE_BUILD_FONT_BAKER` CMake option (default `ON`); with it
`OFF` neither library is configured or linked, and `Font` still loads any atlas
already present in `.cache/fonts/`.

Two dependencies are **NOT** submodules and must be placed manually or the CMake configure step fails with a FATAL_ERROR:
- `lib/glad/` — generate from the GLAD web service (OpenGL loader), place its `include/` and `src/` folders here.
- `lib/stb/` — download `stb_image.h`, `stb_image_write.h`, `stb_perlin.h` from the stb repo; `stb_impl.cpp` provides the single-translation-unit implementation.

```bash
# Configure + build (from repo root)
cmake -S . -B build -G Ninja
cmake --build build

# Run — the working directory MUST be the repo root, because assets and the
# log file are referenced by relative paths like "game/assets/..." and
# "game/output/log.txt". VS Code sets cmake.debugConfig cwd to the workspace root.
./build/game/game.exe
```

There is **no test framework**. The "tests" in `game/src/tests_scenes/` are interactive demo `main`-like functions (`ecs_test`, `piano_demo`, `file_management_test`, `batch_renderer_test`, `tilemap_test`, `text_rendering_test` — the font/text/layout demo, which also logs a numeric layout proof at startup — and `ui_test`, the retained-UI scene: a panel/sidebar/content tree built through `UIManager`, solved by `UILayoutCalculator` and drawn by `UINode`'s debug quad) declared in `game/include/test_funcs.hpp`. To switch which scene runs, edit the call in [game/src/main.cpp](game/src/main.cpp). Only one runs per build.

`DEBUG` is defined unconditionally in the root [CMakeLists.txt](CMakeLists.txt); logging macros compile to no-ops when it is absent. OS is injected as the `OS_NAME` macro (compared against `OS_WINDOWS`/`OS_MACOS`/`OS_LINUX`).

## Architecture

### Layering
`game` (executable) → depends on → `engine` (static lib) → depends on → `lib/*` (glfw, glad, stb, miniaudio, nlohmann_json). The game never touches third-party libraries directly. Include everything engine-side via the single umbrella header [engine/include/EngineInclude.hpp](engine/include/EngineInclude.hpp); everything lives in `namespace Engine`.

### Include-aggregator convention
Every subsystem folder has a `*Include.hpp` (e.g. `CoreInclude.hpp`, `GraphicsInclude.hpp`, `ComponentsInclude.hpp`) that re-exports the folder's public headers. When adding a new type to a subsystem, add its header to the corresponding `*Include.hpp` so it flows up to `EngineInclude.hpp`. Sources are glob-collected by CMake (`file(GLOB_RECURSE ... src/**.cpp)`), so new `.cpp` files are picked up on the next configure but **new files require re-running CMake configure**, not just build.

### Global managers are Singletons
Core services are accessed as `Xxx::get()` via the CRTP base [utils/Singleton.hpp](engine/include/utils/Singleton.hpp): `WindowManager`, `ViewContext`, `Renderer`, `Input`, `Time`, `Logger`, `ResourceManager`, `AudioManager`, `TilemapManager`, `TypeRegistery`. Constructors are private with `friend class Singleton<...>`.

### ViewContext — the active window + camera
[core/window_management/ViewContext.hpp](engine/include/core/window_management/ViewContext.hpp) owns "which window am I working on and what camera is looking at it": the active window id, the active camera entity, its view-proj matrix and visible `WorldBounds`, plus `screenToWorld`/`worldToScreen`/`getMouseWorldPos`. `Renderer`, `TilemapRenderer` and `Input` all read from it rather than holding or re-receiving that state. Per window each frame, `setActiveWindow(id)` comes first — `Input::update()` picks its window from here — then `updateCamera(registry)` once the camera has been moved. Cull with `isVisible(pos, halfExtents)`; the bounds are already widened for a rotated camera.

### ECS (custom, EnTT-like)
Located in `engine/include/ecs/`. Not EnTT — a hand-rolled equivalent.
- `Registry` owns entities and one `SparseSet<T>` component pool per type, keyed by a runtime type id from `TypeRegistery`. It also holds singleton-style "contexts" (`setContext`/`getContext`).
- `EntityHandle` is the ergonomic wrapper: `registry.create()` returns a handle; use `.emplace<T>()`, `.get<T>()`, `.tryGet<T>()`, `.contains<T>()`, `.remove<T>()`. Multi-get returns a `std::tie` tuple.
- `View<Components...>` iterates entities having all listed components, yielding `[entity, comp&, ...]` structured bindings.
- Entities use a generation/free-list scheme; `destroyDeferred` + `flush` allow deferred destruction. Component pools expose `onCreate`/`onDestroy`/`onSet` signals (see `ecs/signals/`).

### Rendering (batch renderer + multi-window)
[graphics/Renderer.hpp](engine/include/graphics/Renderer.hpp) is a batched quad renderer (single Singleton). Typical per-frame flow, driven per-window:
1. `WindowManager::createWindow(...)` returns an `IdType`; cameras are entities with `TransformComponent` + `CameraComponent` (the camera's `windowId` binds it to a window).
2. Per window each frame: `ViewContext::setActiveWindow(id)` → `Input::update()` → `ViewContext::updateCamera(registry)` → `beginPass()` → `setShader()` / `clearColor()` → `addQuad(...)` many times → a second `beginPass()` with a post-processing shader → `drawToWindow()` → `window->swapBuffers()`. The Renderer binds the GL context lazily, syncing to `ViewContext`'s active window inside `beginPass`/`beginScene`/`flush`.
3. `GlfwContext::pollEvents()` once after all windows; close windows collected during iteration afterward (don't mutate the window list mid-loop).

Rendering goes through an offscreen FBO then a post-processing pass to the window (see `beginPass`/`drawToWindow`/`drawToBuffer` and the `gl_wrappers/` RAII wrappers: `GlBuffer`, `GlShader`, `GlTexture`, `GlFrameBuffer`, `GlVertexArray`, `GlLayout`). Shaders are single `.glsl` files containing multiple stages (see `game/assets/shaders/`).

### Application — the frame/window loop
[core/Application.hpp](engine/include/core/Application.hpp) owns steps 2–3 above so scenes don't hand-roll them: the `anyWindowOpen` loop, `Time::update`, per-window `setActiveWindow`/`Input::update`, escape/close bookkeeping, `ViewContext::updateCamera`, `swapBuffers` and `pollEvents`. Scene code supplies three `Delegate` phases — `onFrame(dt)` (once per frame), `onWindowUpdate(windowId, dt)` (per window, before the view-proj matrix is baked, so move cameras here), `onWindowRender(windowId, dt)` (per window, matrix ready) — bound with `app.onFrame().bind(&fn)` and run with `app.run()`. Each phase is optional; unbound ones are skipped. The render body (passes, shaders, draw calls) stays entirely in the callback. `tilemap_test`/`batch_renderer_test` show the shape; the manual loop is still valid for scenes needing full control.

### Other subsystems
- **Logging** ([core/logging](engine/include/core/logging)): use `LOG_INFO/LOG_WARNING/LOG_ERROR(fmt, ...)` (std::format-style). Sinks are pluggable (`ConsoleSink`, `FileSink`); add with `Logger::get().addSink<FileSink>(path)`. `setUseAsync(true)` enables async logging. Register a `std::formatter` for a custom type via the `DEFINE_TYPE_FORMATTER` macro. Never use `std::cout`/`std::cerr` directly — always go through the logging macros.
- **Input** ([core/input](engine/include/core/input)): `Input::get().update()` per window, after `ViewContext::setActiveWindow(id)`; axis-based via `addAxis("Name", {posKeys..., negKeys...})` then `getAxis("Name")`; also `keyPressed(KeyCode::...)`.
- **File management** ([core/file_management](engine/include/core/file_management)): typed file entries (`TextFile`, `BinaryFile`, `JsonFile`, `ImageFile`) under an `IFileEntry`/`Folder` tree via `FileManager`.
- **Audio** ([audio](engine/include/audio)): miniaudio-backed `AudioManager` with buses, streams, and instances (`piano_demo` scene exercises it).
- **Fonts** ([graphics/text](engine/include/graphics/text)): `Font` is an `IResource` built from a `.ttf`/`.otf`. Pick `FontAtlasType::Mtsdf` (scales/rotates cleanly) or `FontAtlasType::Bitmap` (crisp at its native `emPixelSize`) via `FontBakeSettings`; the type selects the texture filtering internally. Glyph data comes back as `Glyph`/`FontMetrics` structs in **em units** — multiply by a pixel size. `getUnitRange()` gives the per-vertex factor an MSDF shader needs (`VEC2_ZERO` for a bitmap atlas). Bakes are cached in `.cache/fonts/` as a `.png` + `.json` pair and rebuilt only when the font file's bytes actually change; `FontBaker` is the only code that touches msdf-atlas-gen. **Loading is asynchronous**: the constructor only queues a job on [FontLoader](engine/include/graphics/text/FontLoader.hpp) — a Singleton with **one** worker thread, started lazily on the first submit — and returns, so a cold bake never stalls the frame (it used to freeze the window long enough for Windows to consider it unresponsive). The queue is **shortest-job-first** on an estimated cost (glyph count × atlas area × an mtsdf factor), so a cheap bitmap atlas does not wait seconds behind an mtsdf one; ties keep submission order, and nothing starves because the queue is a startup burst, not a stream. `FontBaker` also asks msdf-atlas-gen for **a quarter** of the cores rather than all of them, and the worker runs at below-normal priority (so a hybrid CPU parks it on efficiency cores) — since the bake is background work and text already reads in the default font meanwhile, finishing sooner is worth less than not starving the render thread, which is what tanked the frame rate during a load. A *small* share, not a fair one: half of a 22-thread machine is still eleven threads fighting one render thread, which was still visible. The thread count is the lever that matters, because msdf-atlas-gen's own threads start at normal priority however the worker that spawned them is set. Until the result lands, every query answers from a **placeholder**: one generic box for every codepoint (a zero-area one for whitespace, so words stay separate), no texture — which `BatchRenderer` resolves to its white 1×1 default — and plausible metrics, so text lays out and draws as a row of solid quads at roughly the right size instead of vanishing. `isValid()` is therefore **true while loading** (it means "usable"); ask `isReady()`/`isLoading()` for the real answer. The worker stops at `FontData` because `adopt()` uploads a `GlTexture`: the handoff is a `shared_ptr<FontLoadJob>` held by both ends (so a `Font` destroyed mid-bake is safe) with one `std::atomic<bool> isDone` release-stored last, and the *const* accessors poll it — `pollLoad()` — so the first query after the bake finishes installs the atlas **on the thread that owns the GL context**, and a `Font` needs no `update()` and no owner. `getLoadVersion()` bumps on adoption; `TextLayoutCalculator::syncFontVersion` compares it against the version a `TextBlock` was solved with and invalidates, which is what makes a cached layout re-solve once the real metrics arrive (the UI rebuilds every frame anyway, so this is for long-lived blocks). `waitForLoad()` deliberately blocks, for the rare caller that needs real metrics immediately — `text_rendering_test`'s startup layout proof is the example. **The default font** lives here too: `FontLoader::getDefaultFont()` bakes a system face (Arial on Windows/macOS, Liberation/DejaVu on Linux) as a small **Bitmap** atlas, created by the *first* `submit` so it is queued ahead of the font that triggered it, or on demand if nothing else ever loads. `resolve(const Font*)` is what every text entry point runs its font through — `TextLayoutCalculator` (both entry points), `TextRenderer::draw(block)` via `TextBlock::getResolvedFont`, and `drawSpan` — and it returns the default when the caller passed **null**, and the default *again* while the caller's own font is still baking. So placeholder boxes are only ever the default font's own loading state: everything else borrows a real face for the second or two it needs, which is the whole reason the default is bitmap (≈20× cheaper per glyph, so "queued first" also means "ready first"). `TextBlock` records **which** font it was solved with, not just its version, because the resolution flips mid-life (borrowed default → real face) and the layout has to be redone at that moment; drawing reads the same `getResolvedFont()`, or it would place one face's glyphs on another's layout.
- **Text rendering** ([graphics/text](engine/include/graphics/text)): `TextRenderer` is a Singleton owning its own `BatchRenderer<TextVertex>` (init it with `TextShader.glsl`). It only *emits* — all layout lives in `TextLayoutCalculator` (below). Two `draw`s: `draw(block, origin, boxSize)` is the real one (walks a solved `TextBlock`'s runs; `boxSize` exists solely to resolve `TextAlignV`, and a zero box means Top), and `draw(font, text, origin, style, spanStyles)` is a convenience wrapper that builds a throwaway `TextBlock` each call — own a `TextBlock` in a frame loop instead. `drawSpan` (baseline pen in → pen out) stays the public chaining primitive for mixing fonts on one line. `origin` is **top-left**; `drawSpan` is baseline-relative. `flush()` is explicit — call it once after all text so everything shares one draw call. One `TextStyle` covers both atlas types and every effect: colour, `letterSpacing`/`lineSpacing`, `italicSkew`, `underline`, `strikethrough`, plus the distance-field ones — `outlineWidth`/`outlineColor`, `boldness` (±weight), `softness` (blur), and `shadowColor`/`shadowWidth`/`shadowSoftness`/`shadowOffset` (a zero offset makes it a centred glow). A `Bitmap` font silently ignores the distance-field ones but keeps colour, spacing, skew and the decorations, since those are geometry. **Every measurement except `size` is in em**, so a style holds its proportions under camera zoom — do not put these in pixels, or effects drift with zoom and a wide glow floods the glyph quad. Outline/glow width is capped by the baked field: see `Font::getMaxEffectEm()`, and raise `FontBakeSettings::distanceRangePixels` (default 4) for wider effects. Positional styling: `"a /sb/s c"` plus a `{styleB}` list; `//s` escapes a literal `/s`, a short style list falls back to the default, and note `"m/s"` reads as a tag. Style-varying data is **per-vertex, never a uniform**, so a uniform would cost one draw call per style. Text draws in world space by default; `setViewProjOverride` swaps in a screen-space matrix (it flushes on change, so submit all world text, then all screen text). `setClipRect`/`clearClipRect` bound the glyphs emitted next — the UI uses this for `overflow`, and unlike the view-proj override it needs **no flush**, since the rect is per-vertex and text under different clips still shares one draw call; glyphs are cut mid-letter rather than dropped whole. Iterate strings with `Utf8::next` — Latin-1 glyphs are multi-byte.
- **Text layout** ([graphics/text/TextLayoutCalculator.hpp](engine/include/graphics/text/TextLayoutCalculator.hpp)): the single owner of wrapping, line boxes and alignment, serving both world-space text and the UI. A `TextBlock` ([TextLayout.hpp](engine/include/graphics/text/TextLayout.hpp)) holds **input and computed output together** — font, text, style, span styles, `TextAlignH`/`TextAlignV`, `TextOverflow`, wrap and `fixedLineHeight` flags, plus the solved `TextRun`s, `TextLine`s and `bounds`. Two entry points: `measureMinMaxWidth(block)` → `{min-content = longest word, max-content = longest line}`, and `calculate(block, availableWidth)` → height, caching everything on the block. A `TextRun` is a per-line, per-span slice whose `offset` already holds x and the **baseline** y, so rendering never re-walks the string. **A line's height/ascent/descent are the max over every style touching it** (CSS line-box rule) and baselines are placed at `lineTop + thatLine'sAscent`, never stepped baseline-to-baseline; `fixedLineHeight` opts out to the default style. Wrapping backtracks to the last space even several spans back, and a word may straddle a `/s` boundary. `availableWidth <= 0` means unbounded, which is how non-wrapping text reuses one code path. Non-obvious invariants: **`TextBlock` is neither copyable nor movable** — its runs hold `string_view`s into its own `std::string`, and a short string moves by copying into the destination's inline storage, silently dangling every view; `setText` clears runs/spans **eagerly** for the same reason. Three dirty flags (spans/widths/layout) with per-setter equality guards make re-setting identical data every frame free, and `setAlignV` dirties nothing because vertical alignment is applied at draw. The calculator itself is **stateless**, so unlike the `measure()` it replaced it is safe to call mid-draw. **Horizontal alignment is baked into run offsets** (the width is final at `calculate` time); **vertical is applied in `TextRenderer::draw`** (it needs a box height only the caller has). `TAB_SPACES`/`FALLBACK_SPACE_ADVANCE` and the whole codepoint→advance rule live once in [TextMetrics.hpp](engine/include/graphics/text/TextMetrics.hpp) — both the measuring walk and the emitting walk call `TextMetrics::step`, so a measured width cannot drift from a drawn one. `TextOverflow` is declared but **not honoured yet**; everything behaves as `Visible`. Exercise with `ui_test`, which logs a numeric proof at startup.
- **UI** ([graphics/ui](engine/include/graphics/ui)): **being rewritten by hand — treat this folder as in flux.** The previous immediate-mode system (`UiSystem`, `UiRenderer`, `UiElement`, `LayoutCalculator`, `ILeafMeasurer`, `TextMeasure`, `UiPresets`, `UiState`) was deleted in `a886a32`; recover it with `git show a886a32^:<path>` rather than assuming any of it still exists. It is **immediate mode**: the whole tree is declared from scratch every frame — `UIManager::clear()`, then `openContainer`/`closeContainer` pairs with `addTextLeaf` between them — so nothing persists between frames and node ids are only valid for the frame that produced them. **Parenting comes from an open stack, never an argument**: whatever container is currently open adopts whatever is added next, a container pushes itself and a leaf does not, and a node added with the stack empty becomes a root (so several independent panels per frame are free). That is why no builder takes a parent id and why the caller never handles one. Unbalanced pairs are logged, not fatal — `closeContainer` on an empty stack and any container still open at `draw()` each log an error and carry on. `clear()` frees the leaves too, which is why `UIManager` owns them rather than the caller: a per-frame rebuild leaves the caller nowhere sensible to keep one. What is here now: `UIManager` (a Singleton owning an `IdIndexedVector<UINode>` plus the leaf objects), `UINode` (parent / firstChild / lastChild / nextSibling links, a `UILayoutConfig`, a `UIContainerStyle`, `isVisible`, and an optional `IUILeafData*`), `UIContainerStyle` (background/border/shadow/etc., all-`std::optional` fields merged by `combine`, where a set field on `other` wins), `UIContainerStyleSpec` (what `openContainer` actually takes: every `UIContainerStyle` field **plus** `onHover`/`onHeld`/`onPressed`/`onReleased`, each a whole style, so a container's reactive look is declared in the call that creates it), and `leaf_types/` (`IUILeafData` → `UITextLeafData`, configured by a `UITextConfig` carrying font, text, style, `spanStyles`, alignment, overflow, wrap and `fixedLineHeight` — one struct so a new `TextBlock` knob costs no signature change; **`font` is normally left null**, meaning the one on `UIManager` (`setFont(const Font*)`, caller-owned and assumed to outlive the UI), and is set per leaf only to mix faces in one UI. `UIManager::getFont()` may itself be null and that is not an error state — the UI owns **no** fallback: a null font travels down into the text path and resolves to `FontLoader`'s default font there, which is the one place that knows how to make one. Two fonts, even of different atlas types, still share one draw call: `texIndex` **and** `unitRange` are per-vertex; `/s` tags work in UI text exactly as in world text). **The state styles are flattened away inside `openContainer`**, which merges base → `onHover` → `onHeld` → `onPressed`/`onReleased` (lowest priority first, so a press keeps the hover's look and overrides only what it names) and stores the single resolved `UIContainerStyle` on the node — `UINode` never learns a state existed, and rewriting `node->style` after the call still works for anything a constant cannot express (`ui_test`'s slider handle tints itself by the live value that way). `onHeld` reads `UINodeState::isActive`, not `isHeld`: the two differ only once the cursor leaves mid-press, and capture is what matches the gesture there — a grip dragged off itself stays lit until release, while the hover-bound flavour is `onHover`'s job anyway. Both structs are generated from **one field list**, the `UI_CONTAINER_STYLE_FIELDS` X-macro in [UIContainerStyle.hpp](engine/include/graphics/ui/UIContainerStyle.hpp), so a new style field is one line and `combine` follows for free. The spec repeats the fields rather than inheriting `UIContainerStyle` because a designated initializer may only name a **direct** member — put them in a base and `{.backgroundColor = ...}` stops compiling at every call site, which is the entire ergonomic point of the struct. `UILayoutConfig` deliberately got **no** such spec: its fields are not optional, so a state override could only replace the whole config rather than merge into it, and a layout that changes with hover feeds this frame's geometry off last frame's hit test — a node that grows on hover can oscillate. A node with no `leafData` is a container; leaves route `measureWidths`/`measureHeight`/`draw` through the leaf, so callers use `UINode` uniformly. **`IUILeafData::draw` deliberately does not take a `UIContainerStyle`** — box styling (painted by the container) and content styling (a leaf's own concern, e.g. `UITextLeafData`'s `TextStyle`/`TextAlignment`/`TextOverflow` living on its `TextBlock`) are fully separate, and the omission from the interface is what makes a future leaf unable to reach into box style by accident. `UILayoutConfig` on each node is the layout input (`UISizeSpec` = `Fit`/`Grow`/`Fixed`/`Percent` with its own min/max, `UIEdges` padding, gap, `UILayoutDirection`, `alignMain`/`alignCross`, floating, clip). `UILayoutCalculator::calculate(rootId, rootSize)` **builds its own flat preorder mirror tree** of `UILayoutNode` (a `const UINode*` plus index links, `minWidth`/`maxWidth` scratch and solved `width`/`height`/`x`/`y`) rather than writing geometry back onto `UINode`, so the retained tree stays pure input and a solve can be thrown away. Five passes, no recursion outside the tree build: intrinsic widths → final widths → intrinsic heights → final heights → positions; `for (i = n; i-- > 0;)` is bottom-up, `for (i = 0; ...)` is top-down. Width and height are **two separate cycles** because a text leaf's height is a function of its final width while width never reads height — protect that or the solve becomes iterative. There is **no** `minHeight`/`maxHeight`: nothing wraps vertically, so a node's intrinsic height is one number stored in `height` and overwritten by the final pass, which is safe only because that pass is strictly top-down. Invariants carried over from the old solver: `Grow` seeds at max-content (seeding at min lets two growers in a `Fit` parent split evenly and wrap the longer one), floating children are excluded from the main-axis sum, the max **and** the n-1 gap fence-post, a clipped axis reports a zero floor so a scroll container can shrink below its content, and the vertical pass never shrinks (overflow is the clip flag's problem). Every geometric pass works in **layout space** — `pos` is top-left anchored and Y-down — `computeClipRects` then runs strictly top-down (free, since the tree is preorder, so a parent's rect is final before its children are reached), intersecting each node's inherited box with its own when `style.overflow` is not `Visible`. Each node keeps **two** rects: `clipRect` bounds its own drawing, `childClipRect` is what it passes down — they differ by the node's own overflow, and keeping them apart is what stops a clipping container from erasing its own shadow, which lives outside its rect by definition. Hit testing tests the same `clipRect`, so a node clipped away is not clickable. Note `UILayoutConfig::clipX/clipY` (sizing) and `style.overflow` (painting) are still separate flags a caller sets together. Before that, a `computeDrawPositions(rootTopLeft)` pass converts once into `drawPos`: the **centre of the rect, Y-up** from a caller-supplied point where the root's top-left goes (`UIManager` passes `UIRenderer::getRootOrigin()`). Placing the root there rather than at draw time is what keeps hit testing correct — `drawPos` is the one value both the renderer and the mouse compare against, so it has to be final. That split is deliberate: solving stays in one convention, and `drawPos` is display-only, matching what the renderer's centre-anchored `addQuad` wants without every draw site redoing the same `+ size * 0.5f` and Y flip. A leaf needing a corner expands back out of it (`UITextLeafData` does, since `TextRenderer` takes a top-left origin). A **root sizes from its own `UISizeSpec`** — nothing is passed in — and since it has no parent box, `Grow`/`Percent` fall back to max-content the way `Fit` does; it is deliberately *not* clamped up to its content floor, because a `Fixed` root narrower than its content is exactly what makes children shrink and text re-wrap. **Hit testing is resolved once per frame**, in `UIManager::clear()` — the last moment before the tree is rebuilt, so it pairs this frame's mouse with last frame's geometry and settles before any `openContainer` asks. `resolveHover` scans the previous frame's snapshot and keeps the **last** hit in paint order (children paint after parents, later roots after earlier ones, so last == topmost; hit order mirrors paint order by construction, and honouring `zIndex` means reordering both together). `isHovered` then **bubbles** DOM-style to every ancestor — a panel stays lit while the cursor is on its children — with `isHoveredDirectly` for the single topmost node; press/release/held ride on the bubbled hover, which does not let two *overlapping* containers both react since only the topmost node's ancestors are in the chain. **Capture**: a press claims the topmost node into `m_activeKey` and holds it until release wherever the cursor goes, suppressing hover on everything else — `UINodeState::isActive` is what a drag reads, since `isHeld` rides on hover and dies as soon as the cursor leaves the widget. Capture survives one frame past button-up so the node that was pressed is the one that sees `isReleased`, and the captured node still only counts as hovered while the cursor is actually inside it, so press-drag-away-release correctly does not fire. Leaves are excluded via `UILayoutNode::acceptsInput` (copied off the `UINode` at build time, since the snapshot drops that pointer): a leaf returns no state, so hitting one would swallow its container's hover. The snapshot **rebases** its index links onto the concatenated vector — they are per root, and an un-rebased parent walk lands in the wrong root. `UIManager::draw()` solves each root and walks the result, handing `drawPos`/`size` to `UINode::draw` — which forwards a container (gated on `isVisible`) to `UIRenderer::addContainerQuad(drawPos, size, style)` or a leaf to its own `draw`. `draw()` is **self-contained**: it pushes the UI matrix into `TextRenderer` (via `setViewProjOverride`, whose flush-on-change is what keeps world text already queued this frame on the world matrix), then walks and flushes **one paint layer at a time** — boxes then glyphs per layer. Paint order is the preorder walk (children above ancestors, later siblings above earlier), and the tree encodes it correctly, but boxes and glyphs are separate batches: flushing once each would put every glyph above every box regardless of the tree. `UILayoutNode::paintLayer` implements `UIContainerStyle::zIndex` as a **layer offset from the parent** — not CSS's sibling-relative meaning — so a node and its subtree rise together and a child can never fall behind its own container. Cost is two draw calls per layer, not per node. It is deliberately not tied to `isFloating`, which is positioning rather than stacking. Exercise with `ui_test`, a gallery of every paintable style with a screen/world toggle (SPACE) and an mtsdf/bitmap font toggle (TAB), plus a side-by-side pair of the same string from both atlases.
- **UI rendering** ([graphics/ui/UIRenderer.hpp](engine/include/graphics/ui/UIRenderer.hpp)): a Singleton owning its own `BatchRenderer<UIBoxVertex>` over [UIBoxShader.glsl](game/assets/shaders/UIBoxShader.glsl), shaped like `TextRenderer` — `init(shader, maxQuadCount)`, `setViewProjOverride`/`clearViewProjOverride`, explicit `flush()`, one lazily created VAO per window context. **One quad carries a whole container**: background (colour and/or image), border ring, corner radius, dash pattern and shadow all come out of a single rounded-box SDF evaluated per fragment, so no style field costs extra geometry and a container whose fill, border and shadow are all invisible emits **none** — which also means an unstyled container is invisible, not a white debug box. Every field is **per-vertex, never a uniform** (a uniform costs one draw call per style), and every varying except the local position is `flat`, since they are per-quad constants. The border's inner edge is the *same* distance field offset by `borderWidth` — offsetting an SDF inserts the correctly shrunken corner radii for free, which is the whole reason not to emit four border quads. The quad is **padded** by `blur + |shadowOffset| + AA_PADDING` so the shadow has somewhere to live and the box's own antialiased fringe isn't cut off by the edge it is smoothing; that is why the fragment derives uv from `halfSize` rather than interpolated corners. Antialiasing is `fwidth` of the distance itself, so an edge stays one screen pixel wide at any zoom. The shadow is **knocked out under the box** the way CSS does it, or a translucent background shows its own shadow through itself, and `shadowOffset.y` is negated on the way in because the style names it Y-down like CSS while everything past that point is the renderer's Y-up draw space. Dashes walk **arc length** around the rounded boundary (straight runs plus quarter-arcs; the first quadrant is measured and the other three mirror onto it), and the period is divided into a whole number of repeats **CPU-side** so the pattern closes at the seam — `UIBorderStyle::Dashed`/`Dotted` are just two period-to-width ratios, keeping the shader generic. **Clipping**: `addContainerQuad` takes an accumulated clip rect and the fragment shader `discard`s outside it. `TextVertex` carries the same rect, set through `TextRenderer::setClipRect`/`clearClipRect` — which deliberately does *not* flush on change the way the view-proj override does, since a per-vertex rect lets text under different clips share one draw call. Unclipped geometry carries a rect far enough out that the test never rejects, so clipping costs one compare and no branch. `cursor` and `transition` remain **not** the renderer's business — they are input and animation concerns. Boxes and glyphs are separate batches, so relative depth between a container and a text leaf is decided by **flush order** — `UIManager::draw()` owns that sequence, so no caller should flush either one by hand. **`setSpace(UISpace)` picks the coordinate space for the whole UI**, `Screen` by default: one unit per window pixel, an `ortho(0,w,0,h)` built from the window alone so the camera cannot touch it. `World` is the niche one — the UI moves and scales with the camera like a sprite, for a nameplate or a diegetic panel. Screen space is deliberately Y-**up**, not the more obvious Y-down: glyph quads are built baseline-up, so a Y-down matrix mirrors every string. The whole flip is therefore one translation in `getRootOrigin()` (the root's top-left → the window's top-left), and `getMouseUiPos()` converts `Input`'s window-centred pixels into the same space, which is how one hit-test path serves both. The three consumers — matrix, root placement, mouse — all read the single `m_space`, so they cannot disagree. **`setSpace` only flushes when the batch is non-empty**, and that guard is load-bearing rather than an optimisation: `setSpace` is naturally called during setup, and flushing there runs `ensureReady` and builds this window's VAO before the render context is bound, after which every draw has a correct matrix, correct vertices, and nothing on screen.
- **UI theming** ([graphics/ui/theme](engine/include/graphics/ui/theme)): `UIThemeManager` is a Singleton holding a resolved `UIThemeColors` (21 named roles), a `UIThemeMetrics` ramp and a string-keyed `unordered_map<string, UITextStyle>`. It lives **outside** `styling/` because it is external to the UI system: `UIManager`, `UILayoutCalculator` and `UIRenderer` read **nothing** from it except the scale. Widgets read roles inline through the `UITheming::colors()` / `metrics()` / `textStyle(name)` shorthands, so restyling a widget class is a theme edit, not a per-call-site one; the theme deliberately holds **no per-widget config presets**, which would couple it to the widget list. **Colours are seed-and-derive**: `UIThemeColorsSpec` is all-`std::optional` (same X-macro idiom as `UIContainerStyle`, one field list generating the optional spec and the plain resolved struct), and `UIThemeColors::resolve` fills `background`/`accent`/`foreground` from the spec or from defaults and derives the other 18 by lighten/darken/mix — so a whole retheme is three lines, while any role named explicitly is left alone. `onAccent` picks white or near-black off the accent's Rec. 709 luminance, so a yellow accent still takes readable text. Status colours (`success`/`warning`/`danger`) are fixed rather than derived: deriving a red from a red accent makes danger invisible. `getThemePresets()` ships seven built-in presets (Midnight, Amber CRT, Deep Sea, Forest Floor, Vaporwave, Rosewater, Brutalist) — most set only the three seeds, and the ones naming more do it because the look depends on it, which is what a preset-plus-edits editor has to preserve: overlay the edited seeds on a *copy of the preset*, not on a theme rebuilt from seeds alone, or Brutalist's square corners vanish the moment a colour is touched. Surface derivation flips direction when `luminance(background) > 0.5`, since lightening a near-white panel to raise it produces no contrast at all — that is what makes a light theme work. Roles the engine does not define go in a `custom` string map (`colors.get("name")`); extra text styles just take a new name. The foreground trio is deliberately **not** called `text*`: of its uses across the widgets only a handful are glyph colours — the rest are icon tints, a slider knob, picker markers and hover borders — and a widget's text colour comes from its `UITextStyle` anyway, so the palette names contrast levels against the background rather than a medium, and `setTextStyle` **combines** onto the built-in of that name rather than replacing it, so overriding `body`'s colour keeps its size. A miss on `textStyle` returns `body`, not an empty style, so a typo reads as wrong-looking text rather than invisible text. `font` is left null throughout every built-in style, which already means "the UI's font" and resolves to `FontLoader`'s default further down. **`UIThemeMetrics::scale` is the one field the UI system reads for itself**: `UIManager::addNode` multiplies every pixel-valued layout field (fixed sizes, min/max, padding, margin, gap, offsets) and every pixel-valued style field (border width, the four corner radii, shadow offset and blur) by it, and `addTextLeaf` passes it into `UITextStyle::resolve` where it scales `size` alone — every other text measurement is em and scales itself. Applying it to the **inputs** rather than to the projection matrix is the whole point: the solve's output stays in real window pixels, so hit testing, clip rects and `getMouseUiPos` need no changes at all, which is also why this subsumes DPI scaling. `Percent`/`Grow` are ratios and are untouched, and `UI_UNBOUNDED` is left alone since it is a sentinel rather than a length. The one trap it creates: `UINodeState::pos`/`size`/`localMousePos` are **solved** geometry, already in real pixels, so anything feeding them back into a config field must divide by the scale first — `UIWidgets::unscale` exists for exactly that, and the window drag, the tooltip anchor and the dropdown/colour-picker popup offsets all use it. Miss it and the value scales twice.
- **Math** ([utils/math](engine/include/utils/math)): custom `Vec2/3/4`, `Mat4`, `Random`, `MathFuncs` — do not pull in GLM.

## What to reach for
Prefer the engine's own systems over the raw STL/third-party equivalent. The game never includes third-party headers directly — the engine wraps each one.

Use the engine's, not the raw version:
- **Math / vectors / matrices** → `Vec2/3/4`, `Mat4`, and the `Math::` free functions (`sin`, `clamp`, `lerp`, `floor`, `perlin2D/3D`, `DEG2RAD`, …). Do **not** include `<cmath>` or GLM. Randomness → `Random::` (`float01`, `rangeInt`, `pointInCircle`, …), not `<random>`.
- **IDs / handles** → `IdType` with `INVALID_ID`/`START_ID` (from [utils/TypeAliases.hpp](engine/include/utils/TypeAliases.hpp)), plus the `uint`/`byte` aliases — never a raw `int`/`unsigned` for a handle. Runtime per-type ids → `TypeRegistery::get().getTypeId<T>()`.
- **Stable-id → value storage** → `IdIndexedVector<T>` ([utils/IdIndexedVector.hpp](engine/include/utils/IdIndexedVector.hpp)): id-keyed, O(1) `get`, swap-remove; derive `T` from `IHasId` to auto-assign ids on `add`. Reach for this before hand-rolling an id/slot map.
- **Global services** → the `Singleton<T>` CRTP (private ctor + `friend class Singleton<...>`).
- **Active window / camera / matrices / screen↔world** → `ViewContext`, never the `Renderer`. It is the single source for the current window id, view-proj matrix, visible bounds and mouse world position.
- **Heap-owned resources** (textures, tilesets, audio, …) → `ResourceManager` + `IResource` (`addResource<T>(...)` → `IdType`, `getResource<T>(id)`).
- **Files** → `FileManager` typed entries (`TextFile`/`BinaryFile`/`JsonFile`/`ImageFile`), not raw `<fstream>`.
- **Entities / game state** → the ECS (`Registry`, `EntityHandle`, `View<...>`), not ad-hoc containers of game objects. UI nodes are the exception: they live in `UIManager`'s own `IdIndexedVector<UINode>`, not in the registry.
- **GL objects** → the `gl_wrappers/` RAII types, never raw `glGen*`/`glBind*`.
- **Console output** → the logging macros, never `std::cout`/`std::cerr`.

**STL is used freely** where there's no engine equivalent: `std::vector`, `std::unordered_map`, `std::string`, `std::array`, `std::pair`/`tuple`, structured bindings, `if constexpr`, fixed-width ints (`<cstdint>`). `std::format`-style formatting comes in through the logging macros.

**Ownership**: managers use **raw owning pointers with manual `new`/`delete`** (e.g. `ResourceManager`, per-context FBOs/VAOs) — smart pointers are not the norm. Match that; don't introduce `unique_ptr`/`shared_ptr` unless extending code that already uses them.

**Third-party libraries**, each reached only through its wrapper: glfw → `WindowManager`/`GlfwContext`; glad → `gl_wrappers/*`/`GladContext`; stb → `ImageFile` + `Math::perlin2D/3D`; miniaudio → `AudioManager`; nlohmann_json → `JsonFile`; freetype/msdf-atlas-gen → `Font` (only ever included by `FontBaker.cpp`).

## Conventions
- Members prefixed `m_`; constants `ALL_CAPS`; types `PascalCase`; methods `camelCase`.
- 4-space indent, `{` on same line except function bodies, Allman-style class access labels (`  public:` indented). No `.clang-format` is committed — match the surrounding file.
- Class member ordering, top to bottom: private vars, public vars, public functions, private functions (see [Renderer.hpp](engine/include/graphics/Renderer.hpp)).
- IDs are `IdType` with `INVALID_ID` sentinel; prefer engine `TypeAliases.hpp` over raw ints.
- **Comments — default to none; rename instead of commenting.** No comments on declarations in `.hpp` files (members, fields, params, function signatures) — the name must carry the meaning. Only exception: a short trailing *format/example* when an encoding can't fit in a name or a short description on a struct that is a bit ambiguis and cant be explaind in one name, e.g. `std::string neighbors;   // 8 chars, e.g. "1x1xxxxx"` (format only, not purpose). In `.cpp` bodies, comment only what the code can't express — a non-obvious step, tricky invariant, magic number, or bug workaround — one line above the block. Never restate or narrate what a line does; comment *why*, not *what*.
